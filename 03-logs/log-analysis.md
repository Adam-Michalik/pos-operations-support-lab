# Application Log Analysis

## Overview

This exercise demonstrates basic application log analysis in a simulated POS environment.

The test application running on the POS-001 Ubuntu Server generates informational messages and simulated error events.

## 1. System Logs and Application Logs

Two types of logs were examined:

- **System logs:** provide information about service lifecycle events, process failures and system activity.
- **Application logs:** contain messages generated by the application, including operational information and application-level errors.

Systemd service logs were inspected using `journalctl`.

Example:

```bash
sudo journalctl -u pos-app -n 20 --no-pager
```

## 2. Application Log File

The test application writes messages to:

`/var/log/pos-app/application.log`

The following commands were used to inspect the log file:

```bash
sudo cat /var/log/pos-app/application.log
sudo tail -n 10 /var/log/pos-app/application.log
```

- `cat` displays the file contents.
- `tail -n 10` displays the last ten lines.

## 3. Filtering Log Messages

The `grep` command was used to find specific messages.

To display error messages:

```bash
sudo grep "ERROR" /var/log/pos-app/application.log
```

To display informational messages:

```bash
sudo grep "INFO" /var/log/pos-app/application.log
```

## 4. Simulated Application Error

The application was modified to generate a simulated payment gateway error every 30 seconds.

Example log entries:

```text
2026-11-22 14:56:13 [INFO] POS Application is running
2026-11-22 14:56:13 [ERROR] Payment gateway connection timeout
```

The service remained in the `active (running)` state while the application continued to generate error messages.

## 5. Key Findings

- System logs and application logs provide different types of diagnostic information.
- Log filtering helps identify recurring errors.
- A running service does not guarantee that all application functions are working correctly.
- Repeated application errors may indicate a communication or configuration issue that requires further investigation.

## Conclusion

This exercise provided practical experience with Linux log inspection, filtering application messages and identifying simulated functional errors in a POS application environment.
